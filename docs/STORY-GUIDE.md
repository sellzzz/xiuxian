# 青云宗剧情扩展指南

## 当前剧情结构

游戏采用“半年一张卡牌”的修仙年表。左右拖动会改变资源、人物好感和因果；向上拖动代表闭关打坐。第一幕不消耗寿元，完成入宗后进入正式修行。

主线目前分为十幕：

1. 拜入宗门：山门测灵、杂役房报到，解锁功法、背包、任务和人缘册。
2. 外门考核：积累修为与声望，争取脱离杂役身份。
3. 后山试炼：妖狼与凝露草，决定战斗路线和兵刃成长。
4. 问心雷劫：在资源求稳与直面天劫之间选择。
5. 内门遴选：进入内门或留在外门执教。
6. 宗门大比：保存实力或登台争名。
7. 筑基洞府：转让机缘或冒险筑基。
8. 魔道压境：护送弟子或镇守阵眼。
9. 掌教之争：成为掌教或退居太上。
10. 魔域与飞升：远征魔域、守护宗门，并决定飞升或留守。

主线之外还有三类内容：

- 人物支线：柳管事、苏晚、白璃分别拥有相识、好感、羁绊和同行路线。
- 多年因果：泉灵、宗门税账、药童会在多年后回响，之前的选择决定后续卡牌。
- 秘境路线：云海裂隙分为万剑古道、百草幽谷和失败撤退路线，并产出不同法宝。

## 新增一张卡牌的推荐流程

优先把内容写成一个事件对象，再决定它属于哪种卡池：

```js
{
  type: '夜巡古钟',
  act: '支线 · 山门夜巡',
  minYear: 6,
  weight: 1.2,
  title: '古钟在无人时响了三声',
  copy: '钟声来自封闭的旧峰，里面可能藏着宗门旧档，也可能唤醒沉睡的邪祟。',
  quote: '“有些声音不是在召唤你，而是在确认你是否听见。”',
  left: '查阅旧档',
  right: '进入旧峰',
  a: { fame: 8, heart: 3 },
  b: { hp: -8, qi: 18 },
  lockedUp: true,
  upHint: '古钟仍在回响，本轮必须先作出选择。'
}
```

事件字段含义：

- `type`：卡牌唯一类型名，条件、关系和奖励都用它关联。
- `act`：章节或支线标签。
- `minYear` / `maxYear`：修行年限窗口。
- `weight`：同一时期出现概率，日常卡牌可以高一些，关键卡牌建议低一些。
- `title`、`copy`、`quote`：卡牌叙事文本。
- `left`、`right`：两个方向；`a`、`b` 是对应数值变化。
- `lockedUp: true`：关键事件禁止上滑打坐，避免玩家跳过剧情。
- `requires...`：人物、境界、法宝、状态、道途等前置条件。

## 内容配置入口

长期改剧情时优先编辑 `config/story-config.js`：

```js
window.QINGYUN_STORY_OVERRIDES = {
  eventConditions: {
    '夜巡古钟': { minYear: 6, ranks: ['杂役弟子', '外门弟子'] }
  },
  eventContent: {
    '夜巡古钟': {
      title: '改写后的标题',
      copy: '改写后的正文',
      left: '左侧选项',
      right: '右侧选项',
      a: { fame: 5 },
      b: { heart: 8 }
    }
  },
  relationshipEvents: {
    '夜巡古钟': {
      left: { steward: 3 },
      right: { spirit: 5 }
    }
  },
  oneTimeEvents: ['夜巡古钟'],
  artifactRewards: {
    '夜巡古钟': { right: 'cloudSeal' }
  }
};
```

`oneTimeEvents` 填写卡牌的 `type`。核心剧情特殊类型本身已经是一次性卡牌；普通自定义卡牌如果只想出现一次，就把类型名加入这个数组。未加入的卡牌会作为日常卡牌重复进入卡池。

## 设计一条完整支线的模板

建议使用四张卡牌：

1. **相遇卡**：介绍人物或问题，记录第一次选择。
2. **发展卡**：用 `minYear`、好感或状态条件延迟出现。
3. **分歧卡**：左右两侧给出不同资源、关系或法宝结果。
4. **回响卡**：用 `causalKey` 或已有状态判断多年后的结果。

每条支线至少保留一个“无条件可继续”的出口，避免玩家因为资源不足或前置条件失效而卡死。关键卡牌建议设置 `lockedUp: true`，日常卡牌不要锁定打坐。

## 数值和叙事建议

- 一张卡牌最好只突出一个主要冲突，资源变化控制在 1—2 个核心属性。
- 左右选项不要简单对应“好/坏”，而应分别代表两种可持续的成长路线。
- 好感变化通过 `relationshipEvents` 配置，人物之间的牵连由 `influenceRules` 配置。
- 法宝奖励用 `artifactRewards` 配置，共鸣用 `resonances` 配置。
- 结局不是单独写死在卡牌里，而是通过境界、声望、宗门状态、同伴和关键胜利共同决定。

## 发布前检查

新增或改写剧情后，在项目根目录执行：

```powershell
node --check src/app.js
node tests/validate-config.js
powershell -ExecutionPolicy Bypass -File tests/smoke-check.ps1
```

如果只是改写 `eventContent`，不需要修改核心循环；如果新增状态字段、特殊结算或新的章节分支，才需要同步初始化、存档迁移、渲染和测试。
